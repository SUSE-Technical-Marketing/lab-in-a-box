IT labs, deployed automatically

· 简体中文

lab-in-a-box从单个JSON或YAML文件创建完整的实验室：您描述的虚拟机、DNS、Kubernetes集群和附加组件。虚拟机可以在您自己的KVM主机、Harvester上运行，或在八个公有云中的任何一个上运行，同一文件适用于所有这些。

为什么选择lab-in-a-box？

  • 一个文件，一个命令。以声明式方式描述虚拟机、Kubernetes集群（RKE2或K3s）和附加组件。setup_lab.py按依赖关系顺序创建它们，无需手动运行virt-install或Ansible。
  • 家庭或云中的实验室，相同的定义。实验室虚拟机在您拥有的KVM主机、Harvester HCI或AWS、Google Cloud、阿里巴巴云、Hetzner、Scaleway、UpCloud、OVHcloud或Exoscale上运行。实验室可以跨多个KVM主机扩展，单个实验室可以通过云间WireGuard叠加网络组合云和位置。
  • 72个预集成的附加组件。Rancher、Longhorn、NeuVector、Harbor、Keycloak、Jenkins、Argo CD、SUSE Multi-Linux Manager/Uyuni、Nextcloud等，以及有意脆弱的演示应用用于安全培训。
  • 跟随代码的网络界面。lab-builder直接从附加组件的架构呈现每个表单。向脚本添加新字段时，无需更改前端即可在UI中显示。
  • 可交换的配置。SLE Micro使用Ignition和Combustion，openSUSE和Ubuntu使用cloud-init，旧镜像使用virt-customize，或使用真实安装ISO进行脚本驱动的安装（AutoYaST、Kickstart、Preseed或AutoInstall）。
  • 实验室文件外的凭据。云和服务凭据可以存在于按帐户加密的文件中（Argon2id密钥派生后接AES-256-GCM和ChaCha20-Poly1305级联）。
  • 容器化测试。每个检查在其自己的独立可用podman容器中运行，预提交钩子运行相关检查。

架构

系统基于两层架构：

虚拟管理程序节点

一个或多个物理机（裸机）带有KVM/QEMU。每个主机实验室虚拟机并在/var/lib/libvirt/images/sources/中保持源QCOW2镜像。NUC、工作站或任何运行KVM的x86_64机器都足够。需要超过单台机器容量的实验室可以扩展到多个KVM主机—见下面的多主机实验室。

自动化VM

虚拟管理程序上作为整个实验室的控制平面的小型虚拟机。提供：

  • DNS — BIND（named）为实验室域提供服务并转发外部查询，以便所有实验室主机名从指向它的任何客户端解析
  • HTTP — 在/srv/www/htdocs/lab_creation/提供配置文件（Ignition、Combustion、cloud-init）
  • 脚本 — 安装在/usr/local/bin/的所有实验室管理命令
  • 网络界面（可选）— lab-builder，lab.json文件的基于浏览器的设计器

所有用户命令都在自动化VM上运行。它通过SSH连接到虚拟管理程序或虚拟管理程序以及创建的虚拟机。初始设置后，不需要对虚拟管理程序的直接访问。

引擎盖下

命令行工具和每个附加组件都在Python 3.11中，驻留在libs/和scripts/中，并安装在/usr/local/lib/lab_creation/中。它们围绕一小组共享库模块（lab_creation.py、backends.py、services.py、spacecmd_common.py等）进行组织。这些不相互依赖。虚拟机创建通过可交换的VMBackend接口执行，具有十个实现：libvirt、Harvester和八个公有云（见计算后端）。附加组件和编排代码在它们之间不会改变。被替换的Bash实现存档在legacy_bash/下—包括原始install_ds389。

工作原理

部署管道

setup_lab.py执行一个固定的阶段序列。对于没有kclusters部分的实验室，两个Kubernetes特定阶段被完全跳过：

虚拟机配置

每个虚拟机的创建方式如下： 1. 确定它驻留的KVM主机（显式kvm_host字段或按可用容量自动选择—见多主机实验室） 2. 在该主机上复制并扩展源QCOW2镜像 3. 根据其config_method从模板生成配置文件 4. 在BIND中注册DNS条目 5. 通过SSH在虚拟管理程序上运行virt-install 6. 等待SSH可用

配置方法由实验室JSON中的config_method控制（每个节点或在common中）：

值 方法 用于
(空，默认) Ignition + Combustion SLE Micro
cloud-init cloud-init ISO openSUSE Leap、Ubuntu
virt_customize 直接在虚拟管理程序上修改QCOW2（virt-customize）—来宾不需要Ignition/cloud-init支持 CentOS 7、旧的RHEL/Debian或任何没有Ignition/cloud-init的镜像
install_iso 从真实安装ISO进行脚本驱动的安装（AutoYaST、Kickstart、Preseed或AutoInstall，通过install_type选择） 没有其他配置路径的发行版

计算后端

可交换的VMBackend接口确定节点的虚拟机创建位置。从其backend字段（或意味着后端的cloud_account）针对每个节点解析一次。默认值为libvirt。每个附加组件和编排脚本以相同的方式与解析的后端通信，不管它是什么：

后端 虚拟机在何处运行
libvirt 您操作的KVM/QEMU虚拟管理程序（默认）
harvester Harvester HCI集群，作为KubeVirt VirtualMachines
aws Amazon EC2
gcp Google Compute Engine
alibaba 阿里巴巴云ECS
hetzner Hetzner Cloud
scaleway Scaleway Instances
upcloud UpCloud
ovhcloud OVHcloud Public Cloud
exoscale Exoscale

Kubernetes设置

虚拟机运行后，setup_lab.py根据JSON的kclusters部分在每个节点上安装Kubernetes。支持RKE2和K3s。一旦集群准备好，其附加组件就会按顺序运行。虚拟机级别的附加组件（分配给单个节点而不是集群）在该节点配置后运行。

库加载顺序

每个脚本按以下顺序读取配置：

  1. /etc/lab_creation.defaults — 系统默认值、路径、包列表
  2. /usr/local/lib/lab_creation/primary.py — 输入验证、配置加载
  3. /etc/lab_creation.cfg — 节点特定设置（REMOTE_HOST、ROOT_SSH_KEY、VIRT_SRV、KVM_HOSTS等）
  4. /usr/local/lib/lab_creation/lab_creation.py — 虚拟机、DNS和编排函数
  5. /usr/local/lib/lab_creation/k8s.py — Kubernetes集群函数

快速开始

要求

  • 能够运行KVM的机器（Intel VT-x或AMD-V启用）
  • 互联网访问（或本地镜像）以下载包和镜像
  • 所选操作系统的QCOW2镜像在虚拟管理程序上的/var/lib/libvirt/images/sources/中

自动化VM特别需要python3.11—工具链显式固定在上面。大多数发行版提供一个较旧的标准python3。如果缺少python3.11，安装脚本将停止。

测试的镜像： - SLE Micro—推荐，与Ignition+Combustion一起使用 - openSUSE Leap Micro—支持，与cloud-init一起使用

步骤1—准备虚拟管理程序操作系统

在硬件上安装SLES或其他支持KVM的Linux发行版。在安装期间，选择： - 网络：创建一个桥接（br0）连接到您的主NIC，使用固定IP - 系统角色：KVM虚拟化主机

步骤2—启动设置脚本

从具有虚拟管理程序SSH访问权的任何Linux机器：

curl https://raw.githubusercontent.com/SUSE-Technical-Marketing/lab-in-a-box/main/install_demo_server_scripts.sh | bash -

这将设置脚本下载到/var/tmp/setup_demo_server/。

步骤3—配置并运行KVM节点设置

cd /var/tmp/setup_demo_server/setup_demo_server/
vim lab.cfg

然后运行设置（用虚拟管理程序的IP替换<IP>，或本地时省略）：

./setup_kvm_node.py <IP>

这配置自动化VM并启动所有必需的服务。

步骤4—配置自动化VM

SSH连接到自动化VM并安装实验室脚本：

ssh <AUTOMATION_HOSTNAME>
./install_automation_node_scripts.sh

cp /etc/lab_creation.cfg.example /etc/lab_creation.cfg
vim /etc/lab_creation.cfg

步骤5—将客户端DNS指向自动化VM

从您的桌面解析主机名：

# Linux（NetworkManager）：
nmcli con mod <connection> ipv4.dns <AUTOMATION_IP>

# 或添加到/etc/resolv.conf：
nameserver <AUTOMATION_IP>

步骤6—构建您的第一个实验室

setup_lab.py examples/cluster.json.template

您可以在下面的示例中找到更多起点。或者，您可以打开网络界面，而不是手动编写JSON。

网络界面（lab-builder）

lab.json文件设计器基于浏览器，在运行时评估项目自己的Python库。它对任何附加组件都没有内置知识。选择一个组件，表单将直接从其架构呈现。向脚本添加字段，UI将在不更改前端的情况下显示它。

# 尝试它的最快方式—除Python外零依赖：
python3.11 webui/run-local.py            # → http://localhost:8677/

对于生产（Apache或独立systemd/init服务，加上HTTPS over自签证书），请参阅README.webui.md。那里描述了三种操作模式、HTTP API和故障排除。
